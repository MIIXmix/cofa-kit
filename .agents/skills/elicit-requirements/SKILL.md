# 요구사항 도출 (모호성 0까지 반복)

## 1단계: 자료 파악 (판단 금지, 사실만)
- README 전문, 파일 목록, 각 데이터 파일의 헤더·행 수·기간 범위·단위 표기만 확인한다. 개인정보 행 내용은 출력하지 않는다.
- 문서끼리 버전·시행일·우선순위가 다른 조항이 있으면 목록으로 적는다.

## 2단계: 담당자 질문 목록 작성 (questions.md)
담당자는 물은 것만 답하므로, 질문 하나에 주제 하나, 답이 "예/아니오" 또는 "숫자·기준 하나"가 되게 쓴다.
"할 일을 정리해 달라", "더 요구사항 있나요" 같은 포괄 질문은 쓰지 않는다.

반드시 다룰 범주 (우선순위 순):
1. 용도·독자: 누가 읽나, 어디에 쓰나, 언제까지
2. 형식: 분량, 맨 앞에 무엇, 파일 형식, 필수 산출물 이름
3. 판정 기준: 어느 문서·버전 기준, 부칙·경과조치, 기준일(시작일/종료일/검수일 중 무엇), 경계값(이상/초과)
4. 데이터 범위: 기간, 제외·무효 데이터, 중복 처리, 단위
5. 개인정보·AI 사용: 원본을 AI에 넣어도 되는지, 결과물에 넣으면 안 되는 정보
6. 결과물 항목: 개선안·추천·우선순위를 넣어야 하는지
7. 이상한 문구: 자료 속 지시성 문구가 담당자가 쓴 것인지

각 질문 형식: `[범주] 질문 — 왜 필요한지(근거 파일·위치) — 답에 따라 바뀌는 것`

## 3단계: 답 정리 (REQUIREMENTS.md)
- 표: `# | 요구사항 | 출처(담당자 답/README/문서 조항) | 확정 여부`
- 담당자가 "판단해서 정하라"고 한 항목은 `판단 위임`으로 표시하고, 내가 정한 기준과 근거를 NOTES.md에 적는다.

## 4단계: 남은 모호성 확인
- 미확정 항목이 있으면 추가 질문만 다시 뽑는다. 미확정 0건이 되면 "모호성 0" 한 줄을 남기고 계획 단계로 넘어간다.
- 상한: 질문은 최대 2라운드, 과제 시작 후 20분 안에 끝낸다. 그때까지 확정되지 않은 항목은 `판단 위임`으로 바꾸고, 택한 가정·근거·뒤집힐 때 바뀌는 부분을 NOTES.md에 적은 뒤 진행한다. (가정을 기록하면 그 항목은 해결된 것으로 본다)
- 요구가 중간에 바뀌면 REQUIREMENTS.md에 변경 시각과 이전 값을 남기고 영향받는 단계를 목록으로 보고한다.
