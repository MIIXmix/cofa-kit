# 방법 선택지 + 트레이드오프 규칙

목표: 방법을 Codex가 혼자 정하지 않는다. 후보를 사람 말로 보여 주고 내가 고른다. 고른 이유는 결정 카드(AGENTS.md 7-1)에 남아 서술형에서 내가 설명할 수 있어야 한다.

## 1. 절차
1. 문제 유형 판정: 아래 A~H 중 해당하는 것을 모두 고른다(대부분 2~4개가 섞인다). 예: 배송 차량 경로 = A 조합 + D 배정(거점) + B 군집(지역) + E 경로 + F 거리. 설비 교체 시점과 예비품 수량 = A 조합 + G 예측 + D 선택. A~H에 맞지 않는 유형이면 같은 형식으로 후보 2~3개를 직접 제시한다.
2. 결과가 갈리는 유형만 후보 2~3개를 표에서 골라 `후보 | 이 데이터에 맞는 이유 | 약점 | 설명 한 줄` 로 보여 주고 추천 1개를 표시한다. 담당자 답(REQUIREMENTS.md)과 데이터 규모(행 수)를 근거로 든다. D, E, H가 들어가면 4장 방법 수준도 함께 고르게 한다.
3. 패키지 확인: 후보를 보여 주기 전에 쓸 수 있는 솔버부터 확인한다. `python3 -c "import importlib.util as u; print({m: bool(u.find_spec(m)) for m in ('numpy','scipy','ortools','sklearn')})"`. (`python3`가 없으면 `python`.) PuLP는 판에 따라 CBC 내장과 API가 달라 쓰지 않는다. 없고 설치가 막히면 표준 라이브러리로 되는 후보로 바꾼다.
4. 내가 고르면(5분 안에 답이 없으면 추천안) 결정 카드를 쓰고 plan-and-scope로 돌아간다.
5. 효과 표(결과가 확정된 뒤, pre-submit B-2 전에 NOTES.md 검증 결과 절에 쓴다): 어떤 유형이든 결과는 기준선과의 차이를 담당자가 쓰는 단위(시간, 건수, 금액, 가동률)로 바꿔 `지표 | 기준선 | 결과 | 차이 | 현장 단위 환산 | 환산 값 출처` 로 낸다. 환산 값(한 건에 드는 시간, 단위당 비용)은 담당자 답이나 제공 자료에 있을 때만 쓴다. 없으면 환산 칸을 비우고 "환산 값 미확인"이라고 쓴다. 임의로 만든 금액이나 가중치를 실제 값처럼 쓰지 않는다.

## 2. 후보표

### A. 데이터 조합 (여러 파일 붙이기)
| 후보 | 언제 | 반드시 확인할 것 |
|---|---|---|
| 키 조인(사번, 코드) | 공통 키가 있을 때 | 조인 전후 행 수, 키 중복, 매칭 실패 수 |
| 코드표 매핑(지점 코드 → 이름, 좌표) | 참조표가 따로 있을 때 | 매핑 안 된 코드 목록 |
| 공간 조인(좌표 → 가장 가까운 지점, 반경 안 후보) | 위치 데이터 | 거리 정의(F), 반경 값 |
| 시간 묶음(시각 → 30분 칸 등) | 시각별로 따로 풀어야 할 때 | 경계 시각이 어느 칸인지(이상/초과) |
| 상태 필터(휴가, 퇴사, 무효) | 집계 전 제외 | 제외 수를 결과 맨 위에 표시 |

### B. 군집화 (비슷한 것끼리 묶기)
위경도로 거리 기반 군집(k-means, DBSCAN 등)을 할 때는 먼저 km 단위 평면 좌표로 바꾼다(경도 1도 길이는 위도에 따라 줄어든다).

| 후보 | 장점 | 약점 |
|---|---|---|
| 규칙 묶음(목적지 × 시간대 × 행정구역) | 설명이 가장 쉬움, 담당자가 바로 이해 | 경계가 임의, 구역 크기 불균형 |
| 격자(일정 크기 칸) | 빠르고 단순 | 칸 경계에서 가까운 사람이 갈림 |
| k-means | 묶음 수 k를 정할 수 있을 때 무난 | 둥근 묶음 가정, 외딴 점에 끌림, 인원 상한 무시 |
| DBSCAN | 밀집 지역과 외딴 사람을 자동 구분 | 반경(eps) 값에 민감 |
| 방향 분할(sweep: 목적지 기준 각도 순으로 자르기) | 한 목적지로 모이는 노선에 잘 맞음 | 같은 방향의 먼 사람과 가까운 사람이 섞임 |
| 용량 제약 묶음(인원 상한까지 그리디로 채움) | 정원 같은 상한이 있을 때 | 순서에 따라 결과가 달라짐 |
| 계층 군집 | 묶이는 단계를 보여 주기 좋음 | 수천 행이면 느리고 메모리 큼 |

### C. 분류 (판정 나누기)
| 후보 | 언제 | 약점 |
|---|---|---|
| 규칙 임계값(예: 대기 N분 초과 → 이탈 예상) | 담당자 기준이 숫자로 있을 때. 최우선 | 경계 근처가 거칠다 |
| 점수 가중합 | 여러 기준을 합칠 때, 가중치는 파라미터 | 가중치 근거를 설명해야 함 |
| 얕은 결정 트리 | 정답 라벨이 있고 규칙으로 설명하고 싶을 때 | 라벨 없으면 불가, 과적합 |
| 로지스틱 회귀 | 확률이 필요할 때, 계수로 설명 | 라벨 필요 |
정답 라벨이 없으면 학습 모델을 쓰지 않고 규칙이나 점수로 한다.

### D. 배정과 선택 (누구를 어디에, 무엇을 몇 개)
| 후보 | 언제 | 약점 |
|---|---|---|
| 최근접 그리디 | 빠른 1차안 | 용량 무시 |
| 집합 커버 그리디(최소 개수로 모두 덮기, 예: 거점 수 최소화) | 시설 수를 줄이고 싶을 때 | 최적 보장 없음 |
| p-median(개수 고정, 총 거리 최소) | 시설 수가 정해졌을 때 | 계산 무거움 |
| 헝가리안(1대1 배정) | 사람과 자리가 1대1 | 1대다는 변형 필요 |
| 용량 있는 배정(그리디 + 넘치면 다음 후보) | 정원 있는 배정 | 순서 의존 |
| 예산 제약 최대 커버 그리디(비용 대비 추가 효과 순, 가장 효과 큰 단일 항목과 비교) | 예산 안에서 무엇을 고를지, 효과가 서로 겹칠 때 | 겹침 계산(무엇이 무엇을 덮나)을 먼저 정의해야 함 |
| 정수계획(선택 변수 + 커버 변수) | 위 문제를 시간 상한 안에 풀 수 있을 때 | 규모와 솔버 설치에 좌우됨 |

### E. 경로와 순서
| 후보 | 장점 | 약점 |
|---|---|---|
| 최근접 이웃 | 가장 단순 | 품질 낮음, 1차안용 |
| Clarke-Wright savings | 한 거점으로 모이는 다수 노선에 표준, 병합 때마다 용량과 시간 검사가 쉬움 | 국소 최적 |
| sweep + 노선 안 순서 정리 | 방향으로 나눈 뒤 순서만 최적화, 설명 쉬움 | 방향 경계가 임의 |
| 개선 단계: 2-opt(순서 뒤집기), relocate(지점 하나 옮기기), 노선 병합 | 어떤 초기안에도 붙일 수 있음 | 시간 상한 필요 |
| OR-Tools 라우팅 | 설치되면 가장 강력, 시간창과 용량 지원 | 오프라인 설치 가능 여부 먼저 확인, 내부 동작 설명 부담 |
| 정수계획(CP-SAT, scipy milp) | 정확해 | 수십 지점 규모까지만 |

### F. 거리와 시간 계산
| 후보 | 언제 | 약점 |
|---|---|---|
| 과제가 준 소요시간표, 거리표 | 주어지면 항상 1순위 | 빠진 쌍이 있을 수 있음(아래 방법으로 채우고 채운 쌍 수를 경고) |
| 직선거리(하버사인) × 도로 보정계수(1.2~1.4) | 표가 없고 외부 지도 API를 못 쓸 때 | 강, 산, 고속도로를 모름. 계수는 파라미터 |
| 평균 속도로 시간 환산 | 시간 제약이 있을 때 | 시간대별 정체 무시, 속도는 파라미터 |
| 자체 호스팅 도로망(OSRM 등) | 시간과 지도 데이터가 있을 때 | 과제 시간 안에는 비추천, 확장안으로만 언급 |

### G. 예측과 이상 탐지 (수명, 불량, 수요, 설정값)
먼저 "어느 시점에 무엇을 예측해 어떤 결정을 돕나"를 한 줄로 적는다. 정답 값(라벨)이 자료에 없으면 학습 모델을 쓰지 않는다. 반도체 자료면 예측은 cofa-semiconductor의 investigation.md를, 설비 연속값의 이상 신호는 spc.md를 따른다.

| 후보 | 언제 | 약점 |
|---|---|---|
| 규칙과 임계값(담당자 기준, 규격 한계) | 기준이 숫자로 있을 때. 최우선 | 기준 밖 패턴은 못 잡음 |
| 단순 기준선(직전 값, 이동 평균, 그룹 평균이나 중앙값) | 항상 같이 낸다. 다른 후보의 비교 기준 | 추세와 조건 차이를 모름 |
| 선형 회귀, 로지스틱 회귀 | 라벨이 있고 계수로 설명하고 싶을 때 | 휘어진 관계에 약함 |
| 트리 계열(결정 트리, 랜덤 포레스트, 그래디언트 부스팅) | 라벨이 충분하고 특징이 여러 종류일 때 | 설명 부담, 과적합. 특징 중요도는 원인이 아님 |
| 통계 관리(미리 고정한 기준 기간의 평균 ± k 표준편차, 관리도) | 라벨 없는 이상 탐지, 한 변수의 연속 측정값 | 감시 구간 값을 넣어 한계를 다시 맞추면 찾으려던 변화가 묻힌다. 비율과 건수 자료에는 그대로 쓰지 않는다 |
| 고장까지 걸린 시간 분포(생존 곡선 Kaplan-Meier, 수명 중앙값) | 수명과 교체 시점. 아직 고장 나지 않은 개체가 섞여 있을 때 | 고장 나지 않은 개체를 빼거나 고장으로 세면 수명이 실제보다 짧게 나온다. 관측 끝까지 절반 넘게 살아 있으면 중앙값은 정할 수 없다 |

순서는 기준선 → 단순 모델 → 복잡한 모델이다. G만 있는 과제는 4장 사다리 대신 이 순서가 방법 수준이고, 5분 안에 내 답이 없으면 기준선과 단순 모델까지만 한다. 기준선보다 나아진 만큼만 보고한다.
모델, 임계값, 기준 기간을 자료로 맞췄으면 어떤 자료든 분할 검사를 코드로 돌려 검사한 대상 수와 위반 수를 출력한다(AGENTS.md 8-3). 담당자 기준을 그대로 옮긴 규칙형은 이 검사 대상이 아니다. 검사 항목: 만드는 구간이 평가 구간보다 앞인가, 각 특징이 예측 시점에 알 수 있던 값인가, 결측 대체와 정규화를 만드는 구간에서만 맞췄나. 새 설비나 새 묶음에 쓸 결과일 때만 같은 개체가 양쪽에 섞이지 않았는지도 검사한다(같은 설비의 앞날을 예측하는 과제는 구간 순서만 본다). 임계값과 모델은 검증 구간으로 고르고, 남겨 둔 평가 구간으로 한 번만 확인한다.
예측이 결정(재고 기준, 점검 시점, 재검사 대상)으로 이어지면 판정 임계값을 설정 파일에 두고 맞힌 건수, 놓친 건수, 헛경보 건수, 대상 수를 함께 표로 낸다. 어느 쪽 손실이 큰지는 담당자에게 묻는다.

### H. 일정과 순서 배정 (작업을 설비와 시간에)
먼저 확인할 것: 작업마다 처리할 수 있는 설비, 공정의 선후 순서, 작업을 시작할 수 있는 가장 이른 시각, 품종이 바뀔 때의 전환 시간, 공정 사이 대기 한도, 납기와 우선 작업, 정비나 비가동 시간대, 이미 진행 중인 작업을 고정하는지. 지표는 납기 지연 건수와 지연 합계, 전체 완료 시각, 설비 가동률, 전환 횟수 가운데 담당자가 정한 순서로 비교한다.
3장을 적용할 때 4번 시나리오 표의 열은 위 지표로 바꾸되 하드 제약 위반 열은 남긴다. 5번의 망가뜨린 결과 5종은 같은 설비에서 시간이 겹치거나 전환 시간이 모자람, 처리할 수 없는 설비에 배정, 비가동 시간대 침범, 선후 순서 위반, 작업 누락이나 중복으로 쓴다.

| 후보 | 언제 | 약점 |
|---|---|---|
| 우선순위 규칙(납기 빠른 순, 처리 시간 짧은 순, 여유 시간 적은 순) | 빠른 1차안, 현장이 쓰는 규칙과 비교하기 쉬움 | 설비 사이 균형과 전환 시간을 못 봄 |
| 그리디 삽입(작업을 하나씩 가장 빨리 끝나는 설비와 시각에 넣기) + 교환, 이동 개선 | MVP 기본값. 설비 조건, 전환 시간, 비가동 시간대를 검사하며 넣기 쉬움 | 넣는 순서에 따라 결과가 달라짐 |
| CP-SAT 구간 변수(작업과 가능한 설비 쌍마다 선택 구간을 두고 하나만 고름, 설비마다 겹침 금지) | 시간 상한 안에 풀리는 규모일 때 | 시간을 정수 단위로 바꿔야 함, 규모에 민감. 품종별 전환 시간은 겹침 금지만으로 표현되지 않아 순서 변수를 더해야 하고 그만큼 무거워진다 |
| 시간 칸 배정 정수계획 | 칸 수가 적고 조건이 단순할 때 | 칸이 많아지면 변수가 급증 |

## 3. 트레이드오프 최적화 공통 규칙 (D, E, H가 들어가면 적용)
1. 제약 표: `제약 | 하드/소프트 | 값 | 출처(담당자 답, 규정 조항)`. 어기면 운영이 불가능하거나 이용자가 사라지는 값은 하드, 민원 수준은 소프트(페널티).
2. 목적함수: 항목별 가중합으로 쓰고 가중치와 모든 임계값은 설정 파일(config)에 둔다. 코드 하드코딩 금지. 담당자가 항목 사이 우선순위를 정했으면 가중합 대신 사전식으로 비교한다. 그리디와 국소 탐색은 (1순위 값, 2순위 값, ...) 튜플로 비교하고, 정확해는 앞 항목을 풀어 허용오차(설정값) 안에 고정한 뒤 다음 항목을 푼다. 이때 4번 시나리오는 가중치 대신 허용오차를 바꿔 만든다.
3. 기준선: 가장 단순한 해법(예: 최근접 그리디, 현재 운영안) 결과를 같이 낸다. 최적화 결과는 기준선 대비 지표로 보고한다.
4. 시나리오 2~3개: 이용자 우선 / 균형 / 운영 우선 가중치로 각각 돌려 `자원 수(차량, 거점 등) | 총비용 | 이용자 불편의 평균과 최대 | 저이용 자원 수 | 하드 제약 위반` 표로 비교한다. 시간이 모자라면 기준선 + 균형 1개만.
5. 독립 제약 검사기: 최적화 코드를 import하지 않는 별도 함수가 결과만 읽어 하드 제약을 전부 다시 검사한다. 검사 대상 수와 위반 수를 같이 출력한다(AGENTS.md 8-3). 검사기를 믿기 전에 일부러 망가뜨린 결과 5종(정원 초과, 시간 상한 초과, 7번 목록에 없는 한 명 누락, 중복 배정, 문제별 하드 제약 1개 위반)을 넣어 다섯 개 모두 잡는지 테스트로 남긴다. (위반 0건이 "검사기가 아무것도 못 본다"는 뜻이 아님을 보인다.)
6. 시간 상한: 개선 단계는 반복 횟수나 초 단위 상한을 파라미터로 둔다. 데이터 갱신 후 다시 돌려야 하므로 한 그룹 계산이 1분을 넘지 않게 한다.
7. 풀 수 없는 사람(어떤 하드 제약도 맞출 수 없는 경우)은 빼고 넘어가지 말고 따로 목록으로 결과 맨 위에 보여 준다.

## 4. 방법 수준 사다리 (D, E, H가 들어가면 후보표와 함께 보여 준다)
방법 수준은 내가 고르고(담당자에게는 결과 지표로 확인만 한다), 기준(무엇을 최대화하나, 무엇이 하드 제약인가)은 담당자가 정한다. AI가 혼자 수준을 올리거나 내리지 않고, 5분 안에 내 답이 없으면 1단계로 시작한다. 고른 수준과 버린 수준은 결정 카드에 적는다.

| 단계 | 방법 | 언제 | 결과와 함께 말할 것 |
|---|---|---|---|
| 0 규칙 | 담당자 기준을 그대로 규칙으로 | 설명이 최우선이거나 시간이 없을 때 | 최적 보장 없음 |
| 1 그리디 + 개선 | 구성 휴리스틱 + 2-opt, relocate 등 시간 상한 개선 | MVP 기본값 | 기준선 대비 수치 |
| 2 정확해 | 정수계획(MILP), CP-SAT | 실측으로 시간 상한 안에 풀릴 때 | 최적 여부 또는 갭 |
| 3 그리디 초기해 + 시간 상한 정확해 | 1단계 해에서 출발해 정확해로 개선 | 내가 고르면, 1단계가 화면까지 동작한 뒤 | 1단계 값, 최종 값, 갭 |

1. 내가 2~3단계를 골랐을 때만, 1단계를 화면까지 붙인 뒤 덧붙인다(plan-and-scope 5번). 정확해가 시간 상한 안에 해를 못 내거나 1단계보다 나쁘면 1단계 해를 쓴다.
2. 초기해 전달은 솔버마다 다르다. OR-Tools CP-SAT는 `model.AddHint(변수, 값)`과 `solver.parameters.max_time_in_seconds`를 쓴다. 제약 계수는 정수만 받으므로 배수를 곱하되 과하게 키우지 않고, 풀기 전에 `model.Validate()`가 빈 문자열인지 확인한다. scipy `milp`는 `options={"time_limit": 초}`만 있고 초기해를 넣을 수 없으니, 1단계 해와 milp 해를 비교해 좋은 쪽을 쓴다.
3. 정확해를 돌렸으면 `현재 값, 최선 상계(최소화면 하계), 갭 %, 종료 사유(최적, 시간 상한)`를 결과와 같이 저장해 운영자 화면에 보여 준다. 돌리지 않았으면 "갭 미계산"이라고 쓴다.
4. 이론 보장은 조건이 맞을 때만 말한다. 예: 그리디의 1−1/e는 개수 제약 최대 커버 기준이고, 예산 제약이나 다른 조건이 붙으면 그대로 쓰지 않는다.
5. 설계 변수 먼저: 수준을 고르기 전에 결정 변수를 모두 적는다(무엇을, 몇 개, 어디에, 어떤 설정으로). 후보 목록이나 고정값으로 묶어 둔 변수는 표시하고, 1단계 뒤 조정할 대상으로 PLAN.md에 넣는다. 놓치기 쉬운 것은 연속 위치, 설정값, 같은 자원의 종류 교체다.
6. 필수 먼저: 하드 조건은 여러 조건을 한 번에 만족하는 선택부터 채워 필수 비용을 줄이고, 남은 예산으로 목적을 키운다.
7. 공간형 문제는 후보 하나가 어느 대상을 덮는지 계산하는 커버 함수 하나를 먼저 만든다. 이산 단계에서는 그 결과를 행렬로 저장해 쓰고, 그리디, 정확해, 미세 조정이 같은 함수로 평가해 수치가 어긋나지 않게 한다(3장 5번 독립 검사기는 이 함수도 import하지 않고 따로 구현한다). 미세 조정은 위치나 설정을 조금씩 움직여 좋아질 때만 받는 국소 탐색으로 하고 시간 상한을 둔다.
8. 개선 회차마다 메인이 `비용 | 목적값 | 바꾼 변수`를 PROGRESS.md에 한 줄씩 쓴다. 개선폭이 작아지거나 MVP 시각이 오면 멈춘다. 감소 수치는 % 포인트인지 상대 감소율인지 함께 적는다.
