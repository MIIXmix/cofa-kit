# 계획·범위 + 협업 기록

과제 안내에 계획 문서·협업 기록의 파일명이나 양식이 있으면 그것을 따른다. 없을 때만 아래 PLAN.md / COLLAB_LOG.md를 쓴다.

## 1. PLAN.md (구현 전에 작성, 내 승인 후 진행)
1. 목표 1문장: 누가, 어떤 상황에서, 무엇을 할 수 있게 되는가
2. 사용 시나리오 3단계 이내 (화면에서 무엇을 누르고 무엇을 보는가)
3. 요구사항 → 기능 → 수용 기준 표
   `# | 요구사항(REQUIREMENTS.md 번호) | 기능 | 수용 기준(입력 → 기대 결과, 숫자로) | MVP 여부`
   수용 기준은 테스트로 바로 옮길 수 있게 쓴다. 예: "수량 0 입력 → 저장 거부, 오류 문구 표시"
4. 범위: MVP(필수) / 여유 있으면 / 하지 않음(이유). 필수 요구사항은 전부 MVP에 들어가야 한다.
5. 구현 순서: 세로 단위(화면+로직+데이터를 한 기능씩 끝까지)로 나눈다. 단위마다 예상 시간.
6. 시간 체크포인트. PLAN.md 맨 위에 실제 과제 시작 시각 S를 적고 마감 E를 계산한다.
   E(제출물 확정 마감) = min(S + 180분, 13:20)  ← 14:00 종료 − 서술형 30분 − 문제 준비 대기 최대 10분
   계획 승인 S+25 / MVP 동작 E−60 / 검증 완료 E−35 / 문서 완료 E−15 / 내가 직접 읽기 E−15~E−10 / 제출 시작 E−10.
   체크포인트를 넘기면 남은 단위를 "여유 있으면"으로 내리고 그 결정을 기록한다.
7. 위험: 기술 위험(미설치 패키지, 포트, 데이터 형식)과 해석 위험(판단 위임 항목) 각 1줄씩.

## 2. COLLAB_LOG.md (작업 내내 누적)
결정이 생길 때마다 한 줄 추가한다. 형식:
`시각 | 무엇을 AI에 맡겼나 | 결과 | 내가 확인한 방법 | 채택/수정/거절 + 이유`
- 담당자 답변으로 계획이 바뀐 경우, 범위를 줄인 경우, AI 제안을 거절한 경우는 반드시 기록한다.
- 이 기록과 git log가 서술형 질문의 근거가 된다.
