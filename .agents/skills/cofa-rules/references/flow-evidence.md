# 0번 작업 순서와 근거 파일

0. 계획 → 구현(MVP 동작 직후 감사 1회) → 검증 → 완료 순서로만 진행한다. 다음 단계로 넘어가기 전에 아래 근거 파일을 evidence/ 에 쓰고 커밋한다. 파일이 없으면 다음 단계 금지. 승인 전 구현 금지. 커밋이 막힌 환경이면 AGENTS.md 6번대로 근거 파일 존재만으로 넘어가고 "커밋 대기"는 PROGRESS.md에만 적는다. 커밋 해시를 적을 칸에는 `대기`라고 쓴다.
   - 계획 `evidence/1_plan.md`: 불명확점 목록, PLAN.md 요약, 수용 기준, 내 승인 여부.
   - 감사 `evidence/2_audit.md`: 감사는 1회만 한다. 시점은 MVP가 동작한 직후, 늦어도 PLAN.md의 "MVP 동작 E−60" 시각이다(그때 MVP가 덜 됐으면 그 시점 코드로 한다). 구현 전 계획 감사는 하지 않는다(계획은 내가 승인한다). auditor 서브에이전트(읽기 전용)가 REQUIREMENTS.md, PLAN.md, 코드를 함께 보고 요구사항 항목마다 충족 여부를 적대적으로 감사하며, 남은 단위 구현과 병렬로 돈다(8-7). 보고를 그대로 붙이고 지적별 조치(반영/기각과 이유)를 적는다. 메인이 직접 감사하지 않는다. 심각도 높음 지적은 검증 단계 전에 고치고, 고칠 시간이 없으면 NOTES.md 남은 한계에 적는다.
   - 구현 `evidence/3_build.md`: 바뀐 파일, 커밋 해시, 계획 대비 달라진 점.
   - 검증 `evidence/4_verify.md`: 실제로 실행한 테스트 명령, 종료 코드, 출력 원문(`명령 2>&1 | tee evidence/4_verify_output.txt`). 명령을 돌리지 않았거나 출력 파일이 없으면 검증 미완료. 통과·실패 수를 출력에서 옮겨 적는다.
   - 완료 `evidence/5_done.md`: 수용 기준별 충족 여부와 근거 파일 위치, 남은 한계.
