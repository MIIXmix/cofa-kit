# 2번 개인정보, 4-2 시각 데이터

2. 개인정보(데이터에 있을 때만):
   - 원본을 AI가 열람해도 되는지 담당자에게 먼저 묻는다. 이 질문은 계획을 막는 질문이다(elicit-requirements 5범주). 답이 없거나 상한 시간을 넘기면 기본값은 **불허**다: 행 내용은 보지 않고 스크립트 집계만 본다. 이 항목은 판단 위임으로 바꾸지 않는다.
   - 모델에 들어가는 것은 내가 출력하거나 읽은 내용이다. 파싱 오류 traceback, `git diff`, 테스트 실패 메시지도 행 값을 찍으므로 스크립트 예외 메시지에는 행 번호와 열 이름만 넣고 값은 넣지 않는다. 원본 변경 확인은 `git diff --stat`으로 한다.
   - 원본은 헤더(열 이름)와 행 수만 확인한다. 스크립트로 직접 식별 열(이름, 연락처, 이메일)을 지우고, 사번처럼 키로 쓰는 열은 결정적 가명 ID로 바꿔 work/에 저장한다. 결정적 = 같은 원래 값이면 항상 같은 ID(예: HMAC-SHA256 앞 12자). 랜덤 ID는 금지한다(데이터를 다시 받으면 버전 간 비교가 깨진다). 이 과정에서 행 내용 출력 금지. 이후 사본만 열람.
   - 가명 ID 키는 처음 한 번만 만들어 gitignore된 `.env`에 저장하고, 스크립트는 `.env`에서 읽는다. `.env`나 키가 없으면 새로 만들지 말고 멈추고 보고한다(키가 바뀌면 모든 ID가 바뀐다).
   - 주소, 좌표, 생년월일처럼 조합하면 사람을 특정하는 준식별자는 계산에 필요하면 남긴다. 단 출력, 화면, 로그에는 집계나 마스킹(좌표 소수 2자리, 주소는 시군구까지)만 보인다.
   - 이 항목은 에이전트가 자료를 볼 때의 규칙이다. 완성된 앱이 실행 중에 원본을 처리하는 방식은 webapp-build 6장(보안 기본값)을 따른다.
   - 결과물 식별정보 0건.
4-2. 시각 데이터는 시간대 유무(naive/aware)와 `Z` 접미사를 먼저 확인한다. Python 3.10 이하 `datetime.fromisoformat`은 `Z`를 읽지 못한다.
