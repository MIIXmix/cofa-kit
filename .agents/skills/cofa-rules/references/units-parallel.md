# 8-4~8-7 작업 단위, 시간, 병렬

8-4. 한 번에 맡기는 구현 단위는 결과 하나(바뀌는 파일 1~3개, 확인 명령 1개)로 끝나고 예상 15분 이내여야 한다. 넘으면 계획 단계에서 쪼갠다.
8-5. PROGRESS.md에 단위마다 `단위 | 작업 | 예상 분 | 시작 | 끝 | 상태(대기/진행/완료/막힘) | 다음 행동`을 적는다(plan-and-scope 5번 표와 같은 열). 시각은 `TZ=Asia/Seoul date +%H:%M`으로 찍는다. 커밋은 단위가 완료되거나 막힐 때만 메인이 한다(8-7).
   세션이 끊기면 새 세션은 PROGRESS.md, PLAN.md, REQUIREMENTS.md, evidence/ 파일 목록, `git log --oneline`, `git status`를 읽고 커밋 안 된 변경부터 확인한 뒤 다음 단위로 이어 간다. `.env` 존재도 확인한다(2번).
8-6. 한 단위의 실제 소요가 예상(plan-and-scope 6번으로 재보정한 값)의 2 배를 넘기면 멈추고 보고한다. 그 단위는 반으로 쪼개 1회만 다시 맡기고, 그래도 실패하면 "여유 있으면"으로 내린다. 긴 호출 중 20분 무응답 감시는 내가(사람이) 한다.
8-7. 병렬: PLAN.md 작업 표에서 같은 병렬 묶음 번호가 붙은 단위(앞선 작업이 모두 끝났고 바뀌는 파일이 서로 겹치지 않음)는 각각 다른 executor에 동시에 맡긴다. 동시 executor는 최대 3개, 넘으면 앞 단위가 끝날 때까지 기다린다. 독립 단위가 없으면 억지로 나누지 않는다.
   - 공용 파일은 병렬 단위가 건드리지 않는다. 공용 파일 = 의존성 파일, 설정, `.gitignore`, `.env.example`, README, 공통 모듈, DB 스키마, 서버 진입 파일(라우트 등록), 화면 진입 파일(`index.html` 등), 테스트 공통 설정(`conftest.py` 등). 이 파일이 바뀌어야 하는 단위는 병렬 묶음 앞이나 뒤에 혼자 둔다.
   - 병렬 단위의 확인 명령은 자기 테스트 파일만 실행한다(전체 테스트 금지). DB와 출력은 단위별 임시 경로를 쓰고, 서버가 필요하면 단위마다 다른 PORT를 쓰며 자동 리로드는 끈다.
   - 커밋과 PROGRESS.md, NOTES.md, evidence/, COLLAB_LOG.md 기록은 메인만 한다. 서브에이전트는 맡은 파일만 고치고 git 쓰기 명령(add, commit, stash, checkout, restore, reset)을 쓰지 않는다. 의존성 추가가 필요하면 고치지 말고 보고한다.
   - 메인은 커밋 전에 `git status --short`로 목록 밖 새 파일(executor가 만든 테스트 등)을 확인하고, 단위마다 `git add <그 단위 파일 경로>` 다음 `git commit -m "..." -- <같은 경로>`로 따로 커밋한다. 결정 카드를 고쳤으면 NOTES.md도 같은 커밋에 넣는다. `git add -A`, `git add .` 금지(다른 단위의 미완성 파일이 섞인다).
   - 한 단위가 막혀도 나머지는 계속 돌린다. 막힌 단위는 커밋하지 않고, 그 단위 파일을 `parked/<단위 번호>/`로 옮긴 뒤 PROGRESS.md에 '막힘'으로 적는다. 전체 테스트는 parked/를 빼고 돌린다(pytest면 `--ignore=parked`).
   - 병렬 묶음이 모두 끝나면 메인이 전체 테스트를 1회 돌려 합친 상태를 확인한 뒤 다음 묶음으로 간다.
   - auditor는 읽기 전용이라 executor와 동시에 돌려도 된다. verifier는 구현이 끝난 뒤 1회만 돌린다(independent-verify).
   - 이 환경에서 중첩 금지가 설정으로 강제되지 않을 수 있다. 서브에이전트는 다른 서브에이전트를 만들지 않는다.
