# 웹 서비스 구현

## 1. 스택 결정 (첫 단위 전에 1회, 근거와 함께 보고)
1. 과제가 제공한 시작 코드·package.json·requirements.txt가 있으면 그 스택을 그대로 쓴다.
2. 없으면 설치 확인(`node --version`, `python3 --version`, `pip --version`) 후 의존성이 가장 적은 조합을 고른다.
   기본값: Python FastAPI(또는 Flask) + 정적 HTML/JS 1페이지 + 저장은 JSON 또는 SQLite 파일.
   프런트 빌드 도구(React·Vite 등)는 과제가 요구할 때만 쓴다.
3. 의존성은 requirements.txt 또는 package.json에 버전과 함께 적는다.

## 2. 서버 규칙
- 호스트 0.0.0.0, 포트는 환경변수 PORT(기본 8000 등)로 받고 시작 시 "listening on 0.0.0.0:<포트>"를 출력한다.
- 서버처럼 계속 실행되는 명령은 Codex가 직접 붙잡고 있지 않는다. 실행 명령 한 줄을 나에게 주고, 내가 별도 터미널 탭에서 실행한다.
- 코드 변경 후 재시작이 필요하면 그렇다고 말한다(자동 리로드 옵션이 있으면 사용).

## 3. 구현 순서 (PLAN.md의 세로 단위마다 반복)
1. 로직 함수 → API → 화면 순으로 한 기능을 끝까지 만든다.
2. 해당 기능의 자동 테스트를 같이 만든다(webapp-test 스킬 기준) 후 실행해 결과 숫자를 보고한다.
3. Browser 미리보기에서 내가 확인할 것 3줄 이내: 포트, 경로, 누를 것과 기대 화면.
4. 커밋: "[단위N] 기능명 — 수용 기준 #번호 충족".

## 4. 화면이 반드시 처리할 상태
- 빈 데이터, 잘못된 입력(오류 문구), 처리 중, 실패(서버 오류) 상태를 화면에 표시한다. 조용히 아무 일도 안 일어나는 버튼은 없게 한다.
- 판정·경고·제외 같은 중요한 결과는 첫 화면 위쪽에 보이게 한다.
- 개인정보는 화면·로그·응답에 출력하지 않는다(AGENTS.md 2번).

## 5. 마무리
README.md에 "설치 → 실행 → 접속 경로 → 테스트 실행" 4줄을 쓴다. 새 터미널에서 이 4줄만으로 다시 띄워지는지 확인한다.
